我要做一个 3D Boss 战 demo，用来丰富实习简历（目标岗位：游戏客户端开发）。我负责提供想法和设计，大部分实现由你完成。但我需要在面试时能讲清楚每个系统的设计，所以请严格遵守下面的工作方式。

> 此文记录项目初始提案。玩家当前的攻击与防御规则见 [DESIGN.md](DESIGN.md) 第 2 节和 [M2 战斗核心](M2_战斗核心.md)。

## 环境

- Unity 6000.4，URP，新 Input System，Cinemachine 3.x，ProBuilder 6.x
- Windows，代码用 C#

## 整体基调

- **现代感、科技感的暗影剑客对决**：深色场地 + 高饱和霓虹色的自发光（Emissive）+ Bloom 辉光；UI 简洁、扁平、带科技感
- 节奏比类魂游戏更快，但规则更简单、反馈更明确
- **特效一定要炫酷**：刀光拖尾、瞬移残影、剑气、能量飞镖、受击火花、完美格挡/完美闪避的闪光，这些是这个 demo 的门面

### Boss：持双剑的灵活暗影剑客，体型约为玩家的 1.5 倍

P0：

- 普攻三连斩（近距离，快慢刀）：前两刀左右剑各一次，短暂停顿后双剑在前方交叉劈下
- 技能「瞬身斩」：玩家距离较远时，原地蓄力 → 瞬移到玩家上空 → 短暂停滞 → 向下劈砍
- 技能「剑气」：向前方地面释放剑气，伤害随距离衰减
- 格挡条（韧性）：血条下方的白色条。Boss 不在攻击状态时会格挡玩家的攻击，格挡时只扣少量血量并消耗格挡条；格挡条耗尽后韧性降低，出招更容易被打断
- 【建议新增】破防：格挡条耗尽的那一刻，Boss 进入一段较长的破防硬直，期间受到的伤害提高（配合玩家的「破防重击」）。目的是让格挡条系统有一个明确的奖励时刻
- 向后瞬身闪避：玩家连续攻击时触发概率提高
- 血量低于 50% 进入二阶段（P0 中先用简单版本过渡：短暂无敌 + 特效），二阶段格挡条回满、攻击冷却缩短

P1：

- 技能「旋风斩」：Boss 化身旋风，边攻击边靠近玩家，可以反弹玩家的飞镖
- 二阶段新形态：距离较远时双剑合体为长剑，期间不可打断（只会扣格挡条和血量）；攻击距离更长、技能范围更大；普攻变为四连击（三快一慢）
- 【建议新增】后撤突进：Boss 向后瞬身闪避后，有一定概率立刻接一个向前的突进斩，让「后撤」不只是被动躲避，也能变成进攻的起手

P2：

- 残影系统：
  - Boss 向后瞬身闪避时，在原地留下一个残影；残影保持待机姿态，周围有被风吹动的效果（衣摆、能量粒子飘动）
  - Boss 释放技能时，场上的残影被消耗：残影比 Boss 稍晚一点释放同样的技能，造成 Boss 一半的伤害，释放完之后逐渐消失
  - 残影只模仿技能，不模仿普攻
  - 没有被消耗的残影，一段时间后也会逐渐消失
- 完整的转阶段演出（约 15 秒）：Boss 绕玩家高速奔跑形成包围圈，玩家靠近会被击退；Boss 不断从圈上掷剑，出手前在圈上闪光提示，然后飞向玩家，最后被圈的另一侧吸收；掷剑频率逐渐加快。结束后进入二阶段
- 缴械：长剑形态的第四击命中、且玩家持剑时，触发强制动画：Boss 把玩家的剑打飞，插在远处地面上，玩家变为徒手；靠近地上的剑触发拾取动画，拾取被打断时剑直接回到手中

### 玩家

P0（剑形态）：

- 移动；按住 Shift 奔跑
- 空格翻滚：有无敌帧，如果翻滚躲过了伤害（完美闪避），返还这次消耗的体力
- 左键短按：轻攻击三连；长按蓄力，松开后较慢地举剑向下重击
- 右键格挡：在受击瞬间格挡成功（完美格挡）时，角色发光，此时按左键可以快速打出重击，并且短时间内所有动作不消耗体力
- 【建议新增】破防重击：Boss 处于破防状态时，玩家的重击变成特殊的「破防重击」，伤害大幅提高，并带有特写镜头、更长的顿帧和更强的特效
- 鼠标中键：锁定 / 取消锁定 Boss
- 体力条：静止时恢复较快，走路时恢复较慢，其他动作消耗体力，体力不足时无法执行对应动作

P1：

- 慢动作（按 R）：
  - 进入慢动作后**所有东西都变慢**（包括玩家），画面加上滤镜；再按一次 R，或者特殊技能条耗尽时结束
  - 设计目的：让玩家在 Boss 猛攻时缓一口气，更容易找准完美格挡的时机
  - 特殊技能条：不在使用慢动作时会缓慢恢复；完美闪避、完美格挡成功时额外恢复一点
- 【建议新增】闪避反击：完美闪避后的短时间内按左键，打出一记快速的突进斩
- 按 F 切换武器：剑 / 飞镖 / 拳头
  - 飞镖：**能量飞镖**，造型充满科技感，无限使用，飞出后逐渐消散。轻按左键向屏幕中心方向投掷；蓄力后投出速度更快、颜色不同的特殊飞镖；右键没有格挡
  - 拳头：轻按左键左右拳交替；长按左键蓄力，右拳周围凝聚光芒，松开后向前冲拳并且身体向前瞬移；右键可以格挡，但自己也会受到少量伤害；完美格挡后再按左键，直接快速向前冲拳

P2：

- 第一人称视角，按 V 切换（我已有第一/第三人称切换的代码）

### 美术风格与资源策略

- 低多边形 + 现代科技感（见「整体基调」）
- **素材策略**：网上有**非常合适**的免费素材才直接使用；否则优先用代码和程序化方式生成：
  - 特效：Shader Graph、VFX Graph 或 Particle System、Trail Renderer、程序化生成的网格（比如剑气、能量环）
  - 动作：找不到合适的动画时，考虑程序化动画（Animation Rigging 包、IK、Tween）或调整招式设计，并告诉我取舍

## 工作方式（重要）

1. **先不要写代码**。先根据我的设计输出：
   - 一份简短的设计文档（docs/DESIGN.md）：玩法循环、Boss 招式表（前摇/判定/后摇时长、伤害、距离）、玩家能力参数
   - 系统架构：有哪些模块、各自的职责、模块之间怎么通信
   - 开发里程碑：拆成 6~8 个阶段，每个阶段结束时都能运行、都能看到效果
   - 你认为我的设计中范围过大或者有风险的地方

   然后等我确认，再开始写代码。

2. **一次只做一个里程碑**。每个里程碑完成后：
   - 告诉我需要在 Unity 编辑器里手动做哪些操作（你不能点击编辑器，所以场景搭建、组件挂载、参数设置都要写成清晰的步骤；能用 Editor 脚本自动完成的就用脚本）
   - 告诉我怎么测试，以及应该看到什么效果
   - 在 docs/ 下补充这个系统的说明：它解决什么问题、核心类有哪些、关键的设计取舍，以及"面试时可能被问到的 3 个问题和答案要点"
   - 由我测试通过后，再提交 git，进入下一个里程碑

3. **代码要求**：
   - 一个类只负责一件事，不要出现几百行的"上帝类"
   - 用组件化设计，比如 Health、Hitbox/Hurtbox、状态机这类可以复用的组件
   - Boss AI 用状态机（或者行为树，先说明为什么选它）实现，每个招式是独立的状态或数据，方便增删
   - 调参用的数值放在 Inspector 字段或 ScriptableObject 里，不要硬编码
   - 慢动作会改变时间流速，所有计时、冷却、移动都要正确处理 `Time.timeScale`；需要不受慢动作影响的部分（比如 UI 动画）要明确说明
   - 不要直接手改 .unity / .prefab 文件的 YAML，除非我同意

4. **模型必须可以替换**（我之后会把占位人偶换成 Blender 模型）：
   - 角色的逻辑根物体（CharacterController、脚本、碰撞）和模型（Visual 子物体）分离，换模型只需要替换 Visual 子物体
   - 动画统一使用 **Humanoid** 骨骼类型，依靠 Unity 的动画重定向，让动画在不同模型之间通用
   - 代码里**不要**通过骨骼名称或模型内部的层级路径查找物体；需要骨骼时用 `Animator.GetBoneTransform(HumanBodyBones.xxx)`
   - 武器挂点、特效挂点使用独立的 Socket 物体，运行时挂到对应骨骼上
   - 攻击判定（Hitbox）挂在武器或逻辑物体上，不依赖模型的网格
   - 写一份 docs/MODEL_SWAP.md：说明替换模型的步骤，以及我在 Blender 里制作模型时需要遵守的规范（比例、朝向、骨骼要求、导出设置）

5. **美术资源**：只用可以免费商用的素材（比如 Mixamo 的角色和动画、Kenney、Quaternius、Poly Haven），每次引入素材时说明来源和许可证，记录到 docs/CREDITS.md

6. 遇到需要我做决定的地方（比如手感、难度、视觉效果），给出 2~3 个选项和你的推荐，不要擅自决定

7. 严格按 P0 → P1 → P2 的顺序推进。P0 没有全部完成并打磨好之前，不要开始 P1 的任何内容，即使我提出要求，也请先提醒我。

## 我希望 demo 最终包含（可以根据你的评估调整范围）

- 玩家：移动、翻滚（无敌帧）、轻重攻击、格挡、锁定、体力
- Boss：至少 3 个有明显前摇的招式，二阶段
- 打击感：受击硬直、顿帧（hitstop）、镜头震动（Cinemachine Impulse）、受击特效和音效
- UI：Boss 血条和格挡条、玩家血条、体力条和特殊技能条、胜利/失败界面和重新开始
- 一个封闭、简单、有现代感的 Boss 场地
- 最终产出：可以运行的 Windows 构建版本，以及一份 README（包含 GIF 演示、系统架构图、操作说明），用来放在简历和 GitHub 上
