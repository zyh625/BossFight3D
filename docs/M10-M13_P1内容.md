## 怎么试玩

### 玩家

按 **F** 在 剑 → 飞镖 → 拳套 之间循环（只能在自由移动时切换，HUD 左下角显示当前武器）。三种武器共用同一套按键：

| | 左键 | 按住右键 → 松开 | 左键 + 右键 | 识破 |
|---|---|---|---|---|
| **剑** | 三连斩 | 跃起重击 | 切手技 | 切手技 / 重击出手后 0.2 秒内受击 |
| **飞镖** | 投掷，伤害 12，耗 6 体力 | 蓄力飞镖：更快，伤害 18~34，颜色不同 | 无 | 无 |
| **拳套** | 左右拳循环连打，伤害 9 / 10 | 蓄力冲拳：向前瞬移 5 米后出拳，伤害 38~59 | 切手技（用拳） | 窗口 0.3 秒（剑的 1.5 倍），但仍承受 15% 伤害 |

- 飞镖的瞄准：锁定了 Boss 就自动瞄准它；没锁定时屏幕中心出现准星，准星指哪打哪。
- 飞镖飞出 30 米，末段逐渐缩小消散；数量无限。

### Boss

| 招式 | 什么时候出现 | 怎么应对 |
|---|---|---|
| **旋风斩** | 你在 4.2~5.8 米的中距离时 | 信号灯变绿、双剑平举是前兆。旋转约 2.2 秒，每 0.4 秒一段伤害，会追着你走——拉开距离或翻滚穿过；转完有 1 秒"转晕"的收招可以反击。**旋转期间不要扔飞镖，会被弹回来**（弹回的飞镖是红色的，可以翻滚躲开） |
| **后撤突进** | Boss 后撤瞬身之后有 45% 概率接（二阶段 70%） | 后撤后不要直线追上去。突进方向在出手瞬间锁定，横向翻滚可以躲开 |
| **长剑形态** | 二阶段，你离它 6 米以上时合剑（约 0.9 秒的合剑动作） | 持续 16 秒。攻击距离更远（4.6 米）、四连击（三快一慢）、瞬身斩和剑气范围更大。它不格挡也不会被打断，但你的每一击都同时扣血和扣格挡条——把格挡条打空会把形态打散并直接破防 |

HUD 顶部会显示 Boss 当前的招式和形态。

## M10：旋风斩与后撤突进

### 核心类

| 类 | 职责 |
|---|---|
| `BossWhirlwindState` | 蓄势 → 旋转追击（周期性重开判定）→ 收招 |
| `BossLungeState` | 蓄势 → 锁定方向直线突进并挥砍 → 收招 |
| `BossBrain`（改） | 选招改为遍历一张招式列表做轮盘赌；新增"后撤后是否突进"的判定 |
| `IProjectileReflector` | Combat 层的接口：能反弹道具的角色实现它 |

### 设计取舍

- **多段伤害靠"重开判定"实现**。`Hitbox` 一次开启对同一个目标只结算一次（去重）。旋风斩每 0.4 秒关掉再开一次，
  每一段都是一次独立的判定，玩家可以对任何一段翻滚或识破，不需要给 Hitbox 加"多段命中"的特殊模式。
- **突进是后撤的派生，不是一个可选招式**。它不进入选招列表，只在后撤收招时按概率触发。
  这样"后撤"这个被动反应获得了威胁，而选招逻辑不需要理解"连招"的概念。
- **选招逻辑从硬编码三个招式改成遍历列表**。原来的实现为连斩、瞬身斩、剑气各写了一个变量和一段分支；
  加第四个招式时改成了通用的轮盘赌。以后新增可选招式只需要在列表里加一项并配置规则。
- **反弹通过接口而不是类型判断**。飞镖不认识 Boss，只问被击中的角色"你是否实现了 `IProjectileReflector` 并且正在反弹"。

### 面试问答

**Q：Boss 的 AI 是怎么选招的？加一个新招式要改哪些地方？**
- 每个招式有一条规则：距离范围、冷却、权重。回到追击状态时，筛出"冷却结束且距离符合"的招式，按权重做轮盘赌；刚用过的招式权重减半。
- 加一个可选招式：枚举加一项、写一个状态类、在控制器里注册、配置里加一组参数、选招列表里加一项。已有的招式状态不用动。
- 可以补充：为什么不用行为树——这个 Boss 的决策只发生在"选下一招"的瞬间，没有需要持续评估的多层条件。

**Q：一个持续的范围伤害（比如旋风），你怎么做多段命中？**
- 复用已有的"一次判定只打一次"的判定体，按固定间隔重新开启。每次开启清空去重集合。
- 好处：每一段都走同一条伤害管线，无敌帧、识破、顿帧、特效、音效全部自动生效。
- 间隔是数据：调整它就能改变"总共打几段"。

**Q：怎么让 Boss 显得不那么机械？**
- 权重随机 + 刚用过减半，避免固定循环又不至于完全随机。
- 反应式行为：被连续命中时后撤的概率逐次上升；后撤后可能突进——玩家的行为会改变 Boss 的行为。
- 明确的前兆和收招：每一招都有可读的信号（信号灯颜色、武器姿势）和可惩罚的窗口，随机的是"选哪一招"，不是"招式怎么打"。

## M11：武器切换与飞镖

### 核心类

| 类 | 职责 |
|---|---|
| `WeaponForm` | 三种形态的枚举 |
| `PlayerContext`（改） | 持有当前形态；根据形态返回判定体、连段数据、蓄力招式、识破窗口 |
| `EnergyDart` | 飞镖：球形扫掠检测、射程末段消散、被反弹时掉头并交换主人 |
| `DartLauncher` | 瞄准（锁定目标 / 屏幕中心射线）+ 飞镖对象池 |
| `PlayerThrowState` | 投掷的时间线：前摇 → 出手 → 后摇 |
| `WeaponFormVisuals` | 监听形态变化，切换武器外观 |

### 设计取舍

- **形态不是三套状态机，而是同一套状态机读取不同的数据**。左键、蓄力、切手技、识破的流程完全复用；
  形态只决定"用哪份攻击数据、哪个判定体"。只有飞镖因为没有近战判定，多了一个投掷状态。
  代价是 `PlayerContext` 里出现了几处按形态取值的属性；好处是加第四种近战武器只需要配数据。
- **飞镖从手边飞出，但瞄的是相机看到的点**。第三人称下相机和角色不在同一位置：如果让飞镖沿相机方向飞，
  会和准星错开。所以先用屏幕中心射线求出"玩家在看哪个点"，再让飞镖从手边飞向那个点。
  射线的起点要越过角色本身，否则会先打到自己。
- **飞镖用球形扫掠而不是碰撞体**。52 m/s 的蓄力飞镖在 60 帧下每帧走 0.87 米，用 Trigger 碰撞体会直接穿过目标。
  每帧对"这一帧要走的这一段"做 SphereCast，和近战的扫掠判定是同一个思路。
- **对象池**。飞镖预先创建 10 支，循环取用。连续投掷不产生 `Instantiate`。
- **反弹 = 交换主人**。被弹回的飞镖把"主人"改成 Boss，目标自然就变成了原主人；它仍然走同一条伤害管线，
  所以玩家可以用翻滚的无敌帧躲开自己的飞镖。一支飞镖只会被反弹一次，避免来回弹。

### 面试问答

**Q：第三人称射击的瞄准有什么坑？**
- 相机射线和枪口射线不重合。做法是"相机定目标点，枪口朝目标点发射"。
- 相机射线会先打到玩家自己：把起点推到角色前方，或者用层过滤。
- 目标点很近（比如贴墙）时，枪口到目标点的方向会很歪；可以设一个最小瞄准距离。本项目没有处理这一点，是已知的不足。

**Q：高速飞行的子弹怎么保证不穿模？**
- 不依赖物理碰撞回调，每帧主动做扫掠查询（Raycast / SphereCast），长度等于这一帧的位移。
- 也可以用刚体的连续碰撞检测，但要引入刚体和物理步进；主动查询更可控，时机也在自己手里。
- 细节：扫掠起点已经和目标重叠时，命中点是零向量，需要特殊处理。

**Q：三种武器你是怎么组织代码的？为什么不用继承或策略模式？**
- 三种武器的差异主要是数据（时序、伤害、判定体），流程是相同的，所以用"同一套状态 + 按形态取数据"。
- 如果每种武器的流程都不一样（比如弓需要拉弦、法杖需要读条），那就应该给每种武器一个自己的策略对象，状态机把输入转发给它。
- 判断标准是差异在数据还是在流程。飞镖的"出手"流程不同，所以它确实多了一个状态；拳套只是数据不同，就没有。

## M12：拳套

### 做了什么

- 左右拳连打：两段攻击数据循环，没有终结技（剑的三连打完必须重新起手，拳套可以一直打）。
- 蓄力冲拳：复用蓄力状态和攻击状态，攻击数据里的"踏步距离"是 5 米、时间 0.2 秒——速度 25 m/s，看起来就是瞬移，并且自动带残影。
- 拳套的识破：窗口是剑的 1.5 倍，但成功时仍然承受 15% 的伤害，且不进入受击硬直。

### 设计取舍

- **"瞬移冲拳"没有写任何瞬移代码**。它只是一份踏步很远、时间很短的攻击数据。位移仍然走 `CharacterMotor`，
  所以不会穿墙、不会穿过 Boss；残影是 M7 里"观察位移"的组件自动触发的。这是数据驱动 + 表现解耦带来的直接收益。
- **用"带代价的识破"替代原设计的"格挡但自己掉血"**。原设计里拳套右键可以格挡。现在右键是蓄力、防御手段是识破，
  所以把"赤手去接要付出代价"这个意图落在识破上：更容易成功，但有 15% 的穿透伤害。
  实现上是伤害管线里的同一个修饰器多了一个分支：把伤害乘以 0.15 而不是直接取消。
- **拳套的判定体不跟随任何骨骼**，是身前固定的一段胶囊。占位阶段没有手部骨骼；换上人形模型后可以改成跟随手骨，
  但格斗游戏里"判定体不等于模型"是常见做法，固定的判定更可控。

### 面试问答

**Q：你的"瞬移冲拳"是怎么实现的？和 Boss 的瞬移有什么区别？**
- 玩家的冲拳是高速位移：每帧通过 CharacterController 移动，有碰撞，会被墙和敌人挡住。
- Boss 的瞬身斩是真正的传送：直接改位置（先禁用 CharacterController 再启用）。
- 选择依据：玩家的位移必须尊重碰撞，否则可以穿出场地；Boss 的落点是算好的安全位置。

**Q：三种武器之间怎么做平衡？**
- 每种武器有明确的定位和代价：剑均衡；飞镖安全但伤害低、不能识破、会被旋风斩反制；拳套输出快、削格挡条强，但距离短、识破要掉血。
- 数值都在 ScriptableObject 里，可以在运行中调。
- 诚实地说：目前的数值是按设计意图估的，还没有经过充分的试玩迭代。

**Q：识破成功但仍然受伤，为什么不会打断玩家自己的反击？**
- 受击硬直是"掉血且没死"时进入的。拳套识破会掉血，所以要额外排除结算类型为"识破"的情况。
- 这个 bug 在写的时候就预见到了，并且有一条自动化测试专门守着它。

## M13：Boss 的长剑形态

### 核心类

| 类 | 职责 |
|---|---|
| `BossFormState` | 合剑的演出，结束时通知控制器进入长剑形态 |
| `BossController`（改） | `IsLongsword` 以及由它决定的攻击距离、连招数据、技能范围倍率、格挡规则 |
| `BossWeaponRig`（改） | 长剑形态的外观和姿势；判定扫掠轴按比例加长 |
| `BossSkillSettings.LongswordSettings` | 触发距离、持续时间、冷却、各项倍率 |

### 设计取舍

- **形态是控制器上的一个状态位，招式状态不知道形态**。连斩状态只问控制器"第 i 刀的数据是什么""一共几刀"，
  追击状态只问"近战距离是多少"，瞬身斩和剑气只问"技能范围倍率是多少"。所以长剑形态没有复制任何招式代码，
  四连击只是另一组攻击数据。
- **"不会被打断"的代价是"不格挡"**。原设计是"期间不可打断，只会扣格挡条和血量"。实现为：长剑形态下 Boss 不格挡
  （伤害不被削减），每一击同时扣血和格挡条，也不会后撤。这让长剑形态成为高风险高回报的阶段——
  Boss 更凶，但玩家的输出也更直接；把格挡条打空会把形态打散并破防。
- **形态到时间不会打断正在进行的招式**。持续时间到了之后，要等 Boss 回到追击状态才变回双剑。否则一刀挥到一半剑变短了。
- **判定范围跟着模型一起缩放**。判定扫掠轴的两个端点是它的子物体，把轴沿前方缩放 1.45 倍，判定就自动变长，不需要改 Hitbox。

### 面试问答

**Q：Boss 的二阶段 / 多形态，你是怎么避免把每个招式都写两遍的？**
- 形态只改变招式读取的"参数"（数据、距离、范围），不改变招式的"流程"。招式状态通过控制器取这些参数。
- 如果某个形态的某一招流程真的不同，再单独写一个状态；默认情况下共用。
- 反例：给每个招式状态都加 `if (longsword)` 分支，形态一多就无法维护。

**Q：形态切换的时机有什么要注意的？**
- 只在"安全点"切换：进入形态有专门的演出状态；退出形态只在回到追击状态时发生。
- 状态位的改变和外观的改变放在同一个方法里（`BeginLongsword` / `EndLongsword`），避免逻辑和画面不一致。
- 破防会立即打散形态，这是唯一的强制退出，并且也是从一个确定的入口进去的。

**Q：这个 Boss 的难度是怎么递进的？**
- 一阶段：三种基础招式，学会看前兆、翻滚和识破。
- 二阶段：冷却缩短、出手更快，后撤后更常突进。
- 长剑形态：规则变化（不格挡、不被打断、四连击），要求玩家改变打法而不只是反应更快。
- 每一层都保留了反制手段：旋风斩怕拉开和收招反击，长剑形态怕被打空格挡条。

## 已知的不足

- 所有数值都是按设计意图估算的初始值，没有经过试玩调整。
- 占位外观：拳套是两个方块，飞镖是一个菱形长条，长剑是放大的右手剑。
- 飞镖的瞄准点很近时方向会偏；没有做最小瞄准距离。
- 旋风斩的触发距离带（4.2~5.8 米）比较窄，是为了不影响已有招式的触发条件。如果觉得它出现得太少，可以在
  `Data/BossCombatConfig.asset` 的 Skills → Whirlwind → Rule 里放宽。
