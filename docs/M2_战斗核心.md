# M2 战斗核心：状态机、伤害管线、轻重攻击

## 这个系统解决什么问题

1. 玩家从"只会移动"变成"有多种互斥的动作"（移动 / 攻击 / 蓄力），需要一个地方规定**此刻能做什么、什么时候能切到别的动作**。
2. "武器碰到敌人 → 敌人掉血"之间要插入很多规则（无敌帧、格挡、破防增伤……），需要一条可扩展的结算流程，而不是在一个函数里堆 if。
3. 攻击的手感取决于时序（前摇 / 判定 / 后摇）和连招衔接，这些必须是可调的数据。

## 模块与核心类

```
左键按下 / 空格 ─────► InputBuffer ─┐      按住右键 = 蓄力（状态直接读）
 (双键切手技 / 轻击 / 翻滚)           │ 指令
                                      ▼
PlayerController ─► StateMachine ─► Locomotion / Attack / Charge / Roll
   (组装+驱动)                          │ 读 AttackData（时序/数值）
                                        ▼
                    Hitbox（判定期间开启，扫掠检测 + 去重）
                                        │ DamageInfo
                                        ▼
        Hurtbox ─► DamageReceiver ─► [IDamageModifier...] ─► Health
                          │ DamageResult（事件）
                          ▼
               HitFlash / CombatDebugOverlay（表现，只监听）
```

| 程序集 | 类 | 职责 |
|---|---|---|
| Core | `IState` / `StateMachine` | 通用有限状态机，玩家和 Boss 共用 |
| Combat | `Health` / `Stamina` | 生命、体力：只管数值和事件 |
| Combat | `AttackData`（SO） | 一次攻击的时序、伤害、体力、踏步距离、动画名 |
| Combat | `Hitbox` | 跟随武器的攻击判定：扫掠检测、一刀只命中一次 |
| Combat | `Hurtbox` | 受击判定体，指向所属的 `DamageReceiver` |
| Combat | `DamageReceiver` | 受伤的唯一入口，也是结算管线：修饰器 → 扣血 → 广播结果 |
| Combat | `IDamageModifier` | 玩家防御通过它接入，向当前翻滚或攻击状态查询 |
| Combat | `DamageInfo` / `DamageResult` | 结算的输入 / 输出 |
| Player | `InputBuffer` | 输入缓冲：提前按的键在 0.2s 内有效 |
| Player | `PlayerContext` | 各状态共享的引用、配置和切换入口 |
| Player | `PlayerLocomotionState` / `PlayerAttackState` / `PlayerChargeState` / `PlayerRollState` | 移动、攻击、蓄力和翻滚 |
| Player | `PlayerCombatConfig`（SO） | 连段表、蓄力参数、缓冲时长等 |
| Feedback | `HitFlash` | 受击闪白 |
| DevTools | `TrainingDummy` / `CombatDebugOverlay` / `PlaceholderWeaponSwing` | 木桩、调试显示、占位挥剑（都是临时的） |

依赖方向：`Core ← Combat ← Player`；`Feedback`、`DevTools` 只依赖别人，没有任何玩法代码依赖它们。

## 攻击的时间线

```
0 ──── 前摇 ────┬── 判定 ──┬──────── 后摇 ────────┐
   可转向、踏步  │ Hitbox 开 │        ↑衔接点        │ 回到移动
                                     之后可接下一段/蓄力
```

- 时间点全部来自 `AttackData`，由状态里的计时器驱动；动画只是被调整播放速度去适配这个时长。
- 衔接点（`cancelPoint`）之前的后摇不能取消，这是"收招硬直"；之后如果输入缓冲里有轻攻击指令，立刻接下一段。
- 轻击、切手技和翻滚在动作开始时扣体力。蓄力持续扣体力，重击释放时直接使用已付出的蓄力时间计算伤害。
- 识破窗口从攻击状态开始计时。成功后前摇结束，下一次状态更新开启强化判定。返还本招实际消耗，免体力计时由 `Stamina` 统一处理。

## 关键设计取舍

### 1. 时序由数据驱动，而不是动画事件

好处：换动画不丢判定；调手感只改数值，不用进动画窗口挪事件；没有动画（现在的胶囊体）也能完整运行和自动测试。
代价：动画和判定可能对不上（刀还没挥到就判定了）。对策是 `Hitbox` 的 Gizmo 可视化（红色 = 判定中），以及让动画播放速度适配数据时长。精细对齐留到换上正式动画之后。

### 2. 伤害结算做成"管线 + 修饰器"

`DamageReceiver` 按 `Order` 依次调用角色身上的 `IDamageModifier`。玩家翻滚和识破分别返回 `Dodged` 和 `Parried`，并取消这一次扣血。
玩家防御在 100，Boss 格挡可以放在 200。反击的额外削格挡通过 `DamageInfo.GuardDamage` 传给目标，Arena 调试层会显示该值。

### 3. Hitbox 用"每帧主动查询 + 扫掠"，不用 OnTriggerEnter

- 物理回调在 FixedUpdate 节奏下触发（默认 50Hz），而动画在 Update 更新；0.1 秒的判定窗口里物理可能只跑 5 步，快刀会直接穿过目标。
- 主动查询可以放在 `LateUpdate`（动画已更新完骨骼），并在上一帧和这一帧的武器位置之间插值出多个胶囊逐个检测，帧率低也不会漏。
- 判定时机完全由代码控制，不需要 Rigidbody，也不用开关碰撞体。
- 代价：自己维护去重集合；插值是直线近似，挥砍弧度很大时中间位置略有偏差（步长 `maxStepDistance` 可调）。

### 4. 轻攻击和蓄力分到两个键上

第一版是"左键短按轻攻击、长按蓄力"。要区分短按和长按，就必须等到松开或超过阈值才知道是哪种，
所以轻攻击只能在松开时触发，比按下晚约 0.1s，试玩后手感偏"肉"。
左键按下当帧进入轻击。按住右键以 35 点/秒蓄力，1 秒达到满伤害，松键或体力见底时出重击。
按住右键时按左键会发出独立的切手技指令，可在移动、蓄力或轻击衔接点执行。切手技消耗当前这次右键长按，因此随后松键只会重置下一次蓄力。
蓄力期间受击按普通伤害结算。蓄力重击和切手技出手后的前 0.2 秒才允许识破（见 DESIGN.md 2.2 和 7.7）。

### 5. 状态对象复用，通过 `PlayerContext` 互相切换

状态在 `Awake` 里各创建一次，之后反复进入，运行时不产生 GC。状态之间不直接持有对方，而是通过 `PlayerContext` 上的 `TryStartLightAttack` / `TryStartCharge` / `ToLocomotion` 切换——"能不能出招"（缓冲里有指令、体力够）的判断只写在一个地方。

## 面试时可能被问到的 3 个问题

### Q1：为什么用状态机管理角色动作？不用的话会怎样？

答题要点：
- 不用状态机时，通常是一堆布尔值（isAttacking、isRolling、isBlocking…）加上到处的 `if (!isAttacking && !isRolling)`。每加一个动作，所有已有的判断都要补一遍，n 个动作有 n² 种组合，很容易出现"攻击中还能翻滚"之类的非法组合。
- 状态机保证**同一时刻只有一个状态**，每个状态只写"我在的时候做什么、什么条件下去哪"，新增动作 = 新增一个类。
- `Exit` 提供了统一的清理点：攻击状态无论是正常结束、被连段取消还是（以后）被打断，Hitbox 都在 `Exit` 里关闭，不会残留。
- 可以补充局限：纯 FSM 不擅长"同时做两件事"（比如边移动边格挡），那种情况用分层状态机或把可并行的部分做成独立组件；本项目里移动能力就是独立组件 `PlayerMovement`，由状态决定是否调用。

### Q2：一刀砍下去，怎么保证不漏判、也不重复判定？

答题要点：
- **不漏**：判定在 `LateUpdate` 做，此时动画已经把武器移到这一帧的最终位置；记录上一帧的刀根/刀尖位置，按移动距离切成若干步，对每个中间姿态做一次 `OverlapCapsule`，相当于离散的扫掠（连续碰撞检测的思路）。
- **不重复**：一次挥砍开始时清空一个 `HashSet<DamageReceiver>`，命中时先尝试加入集合，加入失败说明这一刀已经打过它了。注意去重的单位是"角色"而不是"碰撞体"，一个角色有多个 Hurtbox 时也只算一次。
- **不打自己**：记录攻击者自己的 `DamageReceiver` 并跳过。
- **卡顿保护**：用"这一刀是否已经开启过判定"而不是"当前时间是否落在判定区间"来决定开启，即使某一帧直接跳过了整个判定窗口，也至少会检测一帧。
- 性能：`OverlapCapsuleNonAlloc` + 预分配缓冲区，不产生 GC；只查 Hurtbox 层。

### Q3：输入缓冲是什么？为什么需要？你是怎么实现的？

答题要点：
- 问题：连招的衔接窗口只有零点几秒，如果必须在窗口内按键，玩家会觉得"按了没反应"。人的习惯是在上一刀还没结束时就按下一刀。
- 做法：按键不直接触发动作，而是写入缓冲并带一个有效期（0.2s）；状态在"允许衔接"的时刻去缓冲里取。提前按的键只要还没过期就能生效。
- 实现细节：只保留最新的一条指令（后按的覆盖先按的，符合"以玩家最后的意图为准"）；取走即清空，防止一次按键触发两次；体力不足时指令也会被消耗掉，避免"体力恢复后角色突然自己出招"。
- 缓冲时长是手感参数：太短等于没有，太长会出现"我早就不想打了它还在出招"。
- 缓冲用的是受时间缩放影响的时间，之后做慢动作时，缓冲的"现实时长"会相应变长，和其他玩法计时保持一致。

## Arena 手动试玩

锁定、受击和顿帧的完整试玩步骤见 [M3 玩家防御与锁定](M3_玩家防御与锁定.md)。

双键组合技在地面举剑下劈，期间隐藏蓄力提示。短时间内先按左键再按右键，可以把轻击起手转成一次组合技并补足体力差额。单独按住右键约 0.12 秒后显示背剑蓄力，释放时跃起下劈。C 键可从地面起跳，受击按 Hurtbox 的实际高度结算。

1. 打开 `Assets/_Project/Scenes/Arena.unity`，进入 Play 模式。先用左键、右键蓄力松开、右键蓄到见底、左右键组合分别试招。调试面板会显示本次命中的伤害和削格挡值。
2. 在 Hierarchy 选中 `TrainingDummy`，勾选 `Sparring Enabled`。走到木桩身边，等屏幕顶部的出拳倒计时小于 0.2 秒时打出切手技或松开蓄力右键。成功会显示「识破」和 3 秒免体力倒计时。
3. 在倒计时约 0.1 秒时按空格，保持在出拳范围内可看到「完美闪避」并收到体力返还。当前胶囊体用位移展示翻滚。Humanoid 可选用 `Roll.fbx`，切手技暂复用 `Heavy`。

## 响应性调整（M5 之后的手感修正）

试玩反馈"按了没反应"，原因和处理：

| 现象 | 原因 | 处理 |
|---|---|---|
| 按下左键后有一小段画面没变化 | 占位剑只在判定阶段才动，前摇 0.18s 内没有任何反馈 | 前摇第一帧就开始拉剑；轻攻击前摇缩短为 0.10 / 0.10 / 0.16 |
| 连按时偶尔丢一刀 | 输入缓冲 0.2s，比"按键到衔接点"的间隔短 | 缓冲加到 0.35s |
| 攻击中想躲躲不掉 | 翻滚也要等到后摇的衔接点 | 轻攻击前摇中、以及任何攻击判定结束后都可以立刻翻滚 |
| 打完想走走不动 | 移动必须等后摇完全结束 | 过了衔接点，推方向键就结束后摇 |
| 滚完有一段什么都做不了 | 翻滚 0.6s 内不接受任何动作 | 0.42s 之后可以直接出刀或再滚 |

取消规则的原则：**防御动作的取消窗口比进攻动作宽**，但切手技和重击的前摇不能翻滚取消——它们是识破的出手，
允许随时滚掉就没有风险了。相关参数：`PlayerCombatConfig` 的 `inputBufferTime`、`rollCancelTime`、
`moveCancelThreshold`，以及每个 `AttackData` 的 `cancelPoint`。
