# M9 慢动作与闪避反击（P1 的第一个里程碑）

## 这个里程碑解决什么问题

1. **慢动作**：Boss 猛攻时给玩家一个"缓一口气"的手段，更容易看清出手、找准识破和闪避的时机。
2. **闪避反击**：识破成功会立即反击，而完美闪避之前只是返还体力——闪避流缺少进攻上的回报。
3. 顺带：场地改为明亮配色，特效相应调整。

## 怎么用

| 操作 | 效果 |
|---|---|
| 按 R | 进入慢动作：所有东西变为 0.4 倍速（包括自己），画面降饱和、偏冷、加暗角 |
| 再按 R / 技能条耗尽 | 结束慢动作 |
| 完美闪避后 0.6 秒内按左键 | 闪避反击：转向刚才攻击你的敌人，突进 3 米并斩击，伤害 30，不耗体力 |

技能条（HUD 左下第三条）：开局满，慢动作每秒（现实时间）消耗 25，所以一整条能用 4 秒；
平时每秒恢复 5；完美闪避 +15，识破 +20。

## 核心类

| 类 | 程序集 | 职责 |
|---|---|---|
| `SkillGauge` | Combat | 技能条数值：自然恢复，监听结算结果在完美闪避 / 识破时加值 |
| `SlowMotionController` | Player | 读 R 键，开关慢动作（改 `Time.timeScale`），按真实时间扣技能条，保证任何情况下都能还原 |
| `SlowMotionFilter` | Feedback | 观察全局时间流速，控制滤镜 Volume 的权重 |
| `PlayerContext.OpenDodgeCounter / TryStartDodgeCounter` | Player | 闪避反击的窗口和触发 |
| `PlayerAttackState.SetupDodgeCounter` | Player | 复用攻击状态执行反击，朝被躲开的攻击者突进 |

## 关键设计取舍

### 1. 慢动作直接改 `Time.timeScale`，靠"两套时间"保证其余部分正确

需求是"所有东西都变慢，包括玩家"，全局时间缩放正好就是这个语义，而且**不需要改任何玩法代码**：
招式时序、冷却、移动、无敌帧、识破窗口、体力恢复从 M1 起就统一使用缩放后的时间（`Time.deltaTime`）。

需要保持正常速度的部分明确使用真实时间（`unscaledDeltaTime`）：

| 用真实时间的部分 | 原因 |
|---|---|
| 技能条的消耗 | 否则慢动作会让自己的燃料也烧得更慢，持续时间和流速设置纠缠在一起 |
| 鼠标转视角、相机跟随（CinemachineBrain 的 IgnoreTimeScale） | 视角不跟手会让人头晕；慢动作应该让玩家"看得更清"而不是"转不动" |
| 滤镜的淡入淡出 | 表现慢动作的滤镜不应该被慢动作本身拖慢 |
| 顿帧的时长、受击闪白 | 它们是给人眼看的反馈，按现实时间才有稳定的观感 |
| UI、退出键的按住计时 | 与游戏内时间无关 |

同时把 `Time.fixedDeltaTime` 按比例缩小：否则物理和 FixedUpdate 在现实中的频率会降到原来的 0.4 倍，画面发卡。

### 2. 慢动作是"信息优势"，不是"数值优势"

玩家自己也变慢，所以慢动作不会让你出刀更快或躲得更远。它提供的是现实中的反应时间：
0.2 秒的识破窗口在 0.4 倍速下相当于现实中的 0.5 秒。这样它不会破坏战斗数值的平衡，
也不需要为"慢动作中的伤害"单独设计规则。

### 3. `timeScale` 是全局状态，必须保证能还原

场景重载不会重置 `Time.timeScale`。如果玩家在慢动作中死亡并点了"再战一局"，新的一局会一直是慢的。
所以 `SlowMotionController` 在 `OnDisable` 里无条件结束慢动作（场景卸载、玩家被禁用都会触发），
并且在每帧检查玩家是否还能操作、是否已经死亡。自动化测试的收尾也会强制还原，避免一个用例失败拖累后面所有用例。

### 4. 滤镜和音效靠"观察时间流速"接入

`SlowMotionFilter` 不引用慢动作系统，它只看 `Time.timeScale` 是否低于正常；`CombatSfx` 播放时按当前流速降低音高。
以后任何原因造成的慢动作（处决演出、转阶段演出）都会自动带上滤镜和低沉的音效，不需要再接线。
这和 M7 里残影"只观察位移"是同一个思路。

### 5. 闪避反击复用攻击状态，而不是新增一个状态

反击的时间线和普通攻击一样（前摇 → 判定 → 后摇，后摇可以接连段），只有三处不同：
朝被躲开的攻击者突进、不消耗体力、不能触发识破。所以给 `PlayerAttackState` 加一个入口 `SetupDodgeCounter`，
而不是复制一个新状态。攻击数据是一份普通的 `AttackData`（`Player_DodgeCounter`），数值可调。

反击方向的问题：翻滚时玩家按着的方向键是**躲避方向**，不能当作攻击方向。
所以结算管线在判定"完美闪避"的那一刻把攻击者记下来，反击时直接转向它。

### 6. 明亮场地下特效改用透明混合

加色混合在亮背景上几乎看不见（见 M7 文档末尾的更新）。这是"换一个美术方向会牵连哪些东西"的一个实例：
因为所有特效共用一份材质，改动集中在一个材质和两处淡出逻辑。

## 调参位置

| 想调什么 | 位置 |
|---|---|
| 慢动作的流速、每秒消耗、最低开启量 | Player 预制体 → `SlowMotionController` |
| 技能条上限、自然恢复、完美闪避 / 识破的奖励 | Player 预制体 → `SkillGauge` |
| 闪避反击的窗口时长 | `Data/PlayerCombatConfig.asset` → Dodge Counter Window |
| 闪避反击的伤害、突进距离、前后摇 | `Data/Attacks/Player_DodgeCounter.asset` |
| 滤镜的强度（饱和度、暗角、色散） | `Settings/SlowMotionVolumeProfile.asset` |
| 场地的明暗和配色 | `ArenaSceneBuilder` 的灯光部分、`ArenaMaterials` 的地面和墙面颜色 |

## 自动化测试

新增 4 条：按 R 开关慢动作并按真实时间扣技能条；技能条耗尽自动结束；
完美闪避后左键打出闪避反击（不耗体力、命中攻击者、技能条增加）；普通翻滚后左键只是轻攻击。

## 面试时可能被问到的 3 个问题

### Q1：你的慢动作是怎么实现的？哪些东西不应该变慢，你是怎么处理的？

答题要点：
- 修改 `Time.timeScale`，并同步缩放 `fixedDeltaTime` 保持物理步进的现实频率。
- 玩法逻辑从一开始就统一用 `Time.deltaTime`，所以自动变慢，没有逐个去改。
- 明确用 `unscaledDeltaTime` 的：技能条消耗、相机和视角输入、UI、滤镜过渡、顿帧时长。说出每一项"为什么"。
- 容易漏的点：协程里的 `WaitForSeconds` 受缩放影响（要用 `WaitForSecondsRealtime`）；Animator 默认受缩放影响（UI 动画要改 Update Mode）；
  粒子系统默认受缩放影响；音频不受影响，需要自己改音高。
- 全局状态的还原：场景重载不会复位 timeScale，必须在 `OnDisable` 里还原。

### Q2：慢动作和你的"局部顿帧"都在操作时间，它们会不会冲突？

答题要点：
- 不会，因为它们操作的不是同一个东西。慢动作改的是全局 `Time.timeScale`；顿帧是每个角色自己的 `LocalHitStop`，
  它让这个角色的状态机不推进、Animator 速度为 0，并用真实时间计算什么时候恢复。
- 如果顿帧也用全局 timeScale 实现，典型的 bug 是：顿帧结束时把 timeScale 设回 1，直接打断了正在进行的慢动作；
  或者两个顿帧重叠时恢复顺序错乱。
- 两者叠加时的表现：慢动作中命中，双方照样顿帧（现实时长不变），顿帧结束后回到 0.4 倍速。
- 这是 M3 做顿帧时就定下的取舍，当时的理由就是"为 P1 的慢动作留路"。

### Q3：闪避反击为什么不新建一个状态？你怎么判断该复用还是该新建？

答题要点：
- 看时间线和转移规则是否相同。反击和普通攻击都是"前摇 → 判定 → 后摇 → 可接连段"，差异只在初始化
  （朝向、体力、能否识破），所以复用同一个状态，用一个专门的入口方法设置差异。
- 反例：翻滚、蓄力的时间线和退出条件完全不同，所以它们是独立的状态。
- 复用的代价是状态里多了条件分支；控制的办法是差异只出现在 `Enter` 的初始化里，`Tick` 的主流程不分叉。
  如果某种攻击开始需要在 `Tick` 里处处判断"我是不是它"，那就是该拆出去的信号。
- 数据上它仍是一份独立的 `AttackData`，调数值不需要动代码。
